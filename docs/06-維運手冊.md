# 06 維運手冊：每週 15 分鐘、每月 1 小時、每年 2 次參數更新

> 設計原則：所有會變的數字都在 `src/config/tw.ts` 與 `src/config/site.ts`，改完跑 `npm run verify` 再 push，Cloudflare 自動部署。不需要碰其他程式。

## 每週 15 分鐘（建議固定星期一）

| 看什麼 | 在哪看 | 正常／異常 |
|---|---|---|
| 網站有沒有掛 | 打開首頁與任一計算機 | 計算機沒反應 → 看 Cloudflare Pages 最近部署是否失敗 |
| 流量趨勢 | GA4 → 報表 → 總覽（比較上週） | 單週掉 > 30% → 看 Search Console 是否有「手動處置」或「安全性問題」 |
| 搜尋曝光／點擊 | Search Console → 成效（28 天） | 關注哪些查詢開始有曝光但 CTR 低 → 調整 title／description |
| 聯盟點擊 | GA4 → 事件 → `affiliate_click` | 有點擊但聯盟後台無轉換 → 連結是否失效、活動是否結束 |
| 收入 | AdSense 首頁、聯盟網／通路王後台 | 記到一張簡單的月表（日期、PV、廣告、分潤） |

## 每月 1 小時

1. **聯盟活動健檢**（20 分鐘）：登入聯盟網、通路王，確認 `OFFERS` 內每個活動仍在進行；下架結束的、新增單價高或核准率高的；調整卡片順序（高單價放前面）。
2. **內容更新**（20 分鐘）：挑 1–2 篇舊文更新數字與 `updatedDate`（Google 對財經內容的「新鮮度」很敏感）。
3. **請款**（10 分鐘）：聯盟網每月 15–23 日、通路王每月 5–15 日；AdSense 達 US$100 自動付款。
4. **備份記錄**（10 分鐘）：把本月 PV、收入、文章數填進月表；對照 `04-執行計畫.md` 的 KPI 看是否該進下一階段。

## 每年參數更新行事曆

| 時間 | 更新什麼 | 檔案位置 | 官方來源 |
|---|---|---|---|
| **1 月初** | 基本工資（月薪、時薪） | `MIN_WAGE` | 勞動部（前一年 9–10 月公告） |
| 1 月初 | 勞保投保薪資分級表上限、勞退提繳上限 | `LABOR_INSURANCE`、`PENSION.maxInsuredSalary` | 勞保局 |
| 1 月 | 勞退基金保證收益（2 年期定存利率） | `PENSION.guaranteedRate` | 勞保局公告 |
| **5 月底（報稅季結束後）** | 把 `INCOME_TAX` 預設年度切換到下一年度 | `tw.ts` 最後一行 `export const INCOME_TAX = INCOME_TAX_115;` | — |
| **11–12 月** | 下一年度綜所稅免稅額、扣除額、級距（財政部 11 月底公告） | 新增 `INCOME_TAX_116` 並加入 `INCOME_TAX_YEARS` | 財政部賦稅署 |
| 12 月底 | 基本生活費（財政部 12 月公告） | 對應年度的 `basicLiving` | 財政部 |
| 隨時 | 青安貸款利率、額度（政策變動） | `YOUTH_MORTGAGE` | 財政部／公股銀行 |
| 隨時 | 房貸、信貸預設利率 | `RATE_DEFAULTS` | 央行五大銀行統計 |
| 每次 | 工具頁的 `updated` 日期 | 各 `src/pages/tools/*.astro` 的 `updated="..."` | — |

### 更新流程（約 30 分鐘）

```bash
git pull
# 1. 編輯 src/config/tw.ts
# 2. 若所得稅級距變了，更新 tests/finance.test.ts 對應的預期值
npm run verify          # 測試 + 建置都要過
git commit -am "chore: 更新 2027 年度參數"
git push                # Cloudflare 自動部署
```

然後在 Search Console 對所得稅、加班費頁「要求建立索引」，讓 Google 盡快抓到新數字。

## 新增聯盟卡片（5 分鐘）

`src/config/site.ts` → `OFFERS` → 對應類別陣列加一個物件（欄位見檔內註解）。`url` 留空的卡片在正式站不會顯示，所以可以先把活動資料準備好、等連結核准再填。

## 常見狀況處理

| 狀況 | 處理 |
|---|---|
| Cloudflare 部署失敗 | 看 build log；多半是 `npm run check` 或測試失敗 → 本機跑 `npm run verify` 修正 |
| AdSense 政策警告（Policy center） | 多為「內容不足頁面放廣告」或「誤導性內容」；依訊息修正該頁或在該頁拿掉 `AdSlot`，請求複審 |
| Search Console「手動處置」 | 極少見；若為「垃圾內容」多半是程式化頁面過多 → 刪除或合併薄弱頁，提交複審 |
| 聯盟連結失效 | 從 `OFFERS` 移除或換新連結；聯盟平台通常會寄活動結束通知 |
| 使用者回報數字錯誤 | 先用 `tests/finance.test.ts` 加一個重現案例，修 `finance.ts` 或 `tw.ts`，測試通過再部署 |
| 想換品牌名／網域 | 改 `site.ts`、`favicon.svg`、`make-og.mjs`；舊網域在 Cloudflare 設 301 到新網域保留 SEO |

## 監控自動化（可選，各 10 分鐘設定）

- **Cloudflare Web Analytics**：免費、無 Cookie；在 Cloudflare 取得 token 填入 `analytics.cloudflareToken`，作為 GA4 之外的備援。
- **Search Console 電子郵件通知**：預設開啟，重大問題會寄信。
- **Uptime 監控**：UptimeRobot 免費方案每 5 分鐘 ping 首頁，掛了寄信。
- **GitHub Actions CI**：已內建，每次 push 自動跑測試與建置，失敗會在 GitHub 看到紅叉。

## 時間總結

| 頻率 | 時間 | 內容 |
|---|---|---|
| 每週 | 15 分鐘 | 看數據、確認網站正常 |
| 每月 | 1 小時 | 聯盟健檢、更新舊文、請款、記錄 |
| 每年 2 次 | 各 30–60 分鐘 | 1 月與 11–12 月參數更新 |
| 持續（可選） | 每週 2–4 小時 | 寫新文章、新工具（階段 1–2 需要，之後可停） |
